# 作品如何保存

每张画布都有自己的数据库，每份作品在其中占一组键。这一篇讲这些键怎么排布，以及为什么最后选择了「没有保存按钮」。

```diagram
works
```

## 键的排布

每张画布的作品放在它自己的 IndexedDB 里：

| 键 | 内容 |
| --- | --- |
| `works:index` | 作品列表（已列出的作品，以及当前的草稿） |
| `works:current` | 画布当前打开的作品 id |
| `work:<id>:<key>` | 这份作品的实时内容，按画布自己的键逐一存放 |
| `work:<id>:local-storage` | 作品不在屏幕上时，它在 localStorage 里的小设置 |
| `saved:<id>:<key>` | 一份快照，只在显式恢复时读取 |

画布永远读写实时副本 `work:`，所以刷新不会丢东西——实时副本就是作品本身。

## localStorage 怎么办

有些小状态（比如当前选中的模板、面板宽度）一直存在 localStorage 里，被同步代码直接读取。为了不改动这些代码，打开中的作品继续使用原来的键；**离开**一份作品时，把这些值复制进它的 `local-storage` 条目，**进入**另一份时再写回去。

## 切换作品：卸下、交换、重新挂载

打开同一张画布的另一份作品时：

1. 先把画布从屏幕上卸下——卸载时会把最后一次改动写进正在离开的作品；
2. 作品库交换 localStorage 的值和当前 id；
3. 以新 id 为 key 重新渲染画布，它从新作品的键里读出一切。

画布自己的「挂载时读取、变化时保存」逻辑完全不用改。

> [!WHY]
> 四张画布各有一套成熟的保存逻辑。如果让作品库去理解每张画布的数据结构，每加一张画布就要改一次作品库。现在作品库只认「键」，不认内容：任何按键存储的画布都能自动拥有多份作品。

## 为什么没有保存按钮

早先的版本有「保存」按钮：草稿自动存，作品只在点保存时更新，离开时还要问一句「保存 / 不保存 / 取消」。用起来却总是多一道心事——这一版到底存了没有？

后来改成和 claude.ai 的对话一样：一份作品有了内容，就自己出现在列表里；屏幕上是什么，保存下来的就是什么；只有什么都没画的空草稿会在离开时被丢弃。`saved:` 快照仍然保留，以备显式恢复。

## 升级与回滚

第一次以作品模式运行时，画布之前保存的内容（旧的键和 localStorage）会自动成为第一份作品。旧键是**复制**而不是移动：如果退回到旧版本，它仍然能找到原来的数据。

> [!NOTE]
> 存储键和数据库名一旦发布就不再改名。改名意味着用户已有的作品在新版本里「消失」，即使数据还在硬盘上。

## 备份格式

设置 → 数据 → 导出，会把四张画布数据库里的所有条目，连同每张画布当前的 localStorage 快照，写进一个 JSON 文件。导入时先校验格式，再清空并逐条写回，最后恢复 localStorage，重新载入页面。
