## 🖌️ 自由画布

一块用来做图的白板：用一句话描述画面，图片就生成到画布上；在图上圈出要改的地方、旁边写上要求，点一下魔棒，修改后的新版本会出现在原图旁边。每个版本都会保留，版本条里能看到每一版改了什么、什么时候改的。

## 🧰 Skills

CanvasAnvil 为每个画布都提供了专用本地 skill，用来保证工作流稳定、输出一致，而不是把所有任务都塞进同一条通用提示链。

- `diagram-skill` · 图表生成与打包
  在 Codex 内打开现有 draw.io 编辑器，通过对话修改 XML，支持手动编辑同步和 drawio/SVG/PNG 导出，数据保存在项目的 `diagram/` 下。在线 draw.io 编辑器需要网络访问。
- `cad-skill` · 室内设计交付流程
  在 Codex 内打开现有户型设计器，通过对话生成方案、执行局部操作和 spec 补丁，支持手动修改同步、设计检查及导出，数据保存在 `cad/` 下。原有离线重建和完整交付脚本继续可用。
- `ppt-skill` · 完整演示稿生产
  强制先确认大纲，再生成整套演示稿，并导出可编辑 PPT、PDF 或图片版 PPT。
- `canvas-skill` · 本地白板图片创作
  Codex 原生画布插件，复用网站的 Excalidraw 白板、标注合成、图片摆放和版本条。画布通过 MCP widget 打开，直接在 Codex 对话中提出生成与修改要求，由 Codex 读取选中图片及标注，调用宿主图片工具生成并回填。数据保存在当前项目的 `canvas/` 下。
  从仓库根目录执行 `codex plugin marketplace add .`，再执行 `codex plugin add canvasanvil-canvas@canvasanvil-local`。安装后重启 Codex，调用 `$canvas-skill`、`$diagram-skill` 或 `$cad-skill` 打开对应画布。运行环境为 Node 20+，发布包包含 MCP 和 widget，无需安装 npm 依赖。

所有 skill 默认使用宿主文本模型。只有生图能力需要单独配置图片生成供应商。
可编辑 PPTX 导出同样用宿主模型：助手按 `skill/ppt-skill/references/editable-pptx-workflow.md` 逐步重建幻灯片，所需脚本都在 skill 的 `editable/` 目录里；另外需要 PowerPoint 和 Python 依赖（`editable/requirements.txt`）。

## 🚀 快速开始

1. 安装依赖

```bash
npm install
```

2. 启动本地开发

```bash
npm run dev
```

默认访问地址：`http://127.0.0.1:8001`

CanvasAnvil 以单服务部署，详细配置见 [deploy/README.zh-CN.md](deploy/README.zh-CN.md)。

3. 运行类型检查

```bash
npm run check
```

4. 构建生产版本

```bash
npm run build
```

## 🧪 常用命令

- `npm run dev`：在 `8001` 端口启动应用
- `npm run check`：执行 TypeScript 检查
- `npm run lint`：运行 ESLint
- `npm test`：运行测试
- `npm run build`：构建生产版本

## 📝 开发说明

- 所有模型调用都走 OpenAI 的 HTTP 协议。想换厂商，只要在设置里把 Base URL 指向它的 OpenAI 兼容端点即可，没有厂商列表可选。
- AI 配置读取本地应用设置；文本通道和生图通道分别配置。
- 本地开发依赖 API 服务提供 `/api/chat` 和 `/api/ppt-ai`。
- 修改 `vite.config.ts` 中的本地 API 路由后，需要重启开发服务。
- `server/**` 使用相对路径导入：`vite.config.ts` 会 import 开发中间件（这样 `npm run dev` 一条命令就带 API），而 Vite 用纯 Node 加载自己的配置文件，不认 `@/` 别名。
- 设置 `PROMPT_LOG_DIR` 可把拼装好的提示词写入磁盘；默认关闭，因为日志里含有用户内容。

## 🗓️ 最近更新

### 2026-11-08

**✨ 新增**

- **室内设计画布改为以可编辑的户型设计器为核心**
  - 画布里内置了完整的交互式户型设计器：2D 平面、3D 鸟瞰和漫游、家具、水电、吊顶、地面铺装、拆改图层、报价和施工图，外观跟随网站主题。AI 生成的每一版户型都在这里打开，可以直接拖动、修改，接着手动设计。
  - **先出方案**：说出需求后，AI 先写设计方案（房间、面积、朝向、动静分区、入户），在对话里以步骤链的形式流式显示；确认方案后才生成户型。
  - **待定事项一键点选**：方案会列出所有能定的事项，分为布局 / 硬装 / 设备 / 电器 / 智能 / 水电六组：厨房形式和橱柜形状、各房间地面、墙面颜色、踢脚线、吊顶、门窗、空调、新风、地暖、热水、智能马桶、智能灯光和窗帘、插座数量、网口、强弱电箱位置、床头 USB、地插。每项都预选了推荐值，想改就点一下，在方案底部确认即可，不用再打一遍字。
  - **AI 只描述，程序来画**：AI 只写布局说明（网格、房间、门窗、家具摆放意图、材质），墙体、门窗和家具位置都由程序计算；家具放不下会自动缩小或换小一号的款式，每处调整都会列出来。
  - **自动收尾**：嵌进墙里或挡住窗帘的家具会自动推开，一键布好水电点位，再按你选的水电偏好调整（插座加密、网口、电箱放入户门旁、餐桌或茶几下加地插、床头 USB）。
  - **水电逐房间审计**：检查灯、开关、插座、开关与灯的对应关系、安装高度、门边开关是否在把手一侧、卧室双控、厨房烟机插座和燃气报警、卫生间防水插座、强弱电箱。问题会列在对话里，以及对话下方可展开的列表里。
  - **从原始户型图开始**：上传照片、截图、PDF 或 DXF，自动识别墙体和门窗，原图作为底图保留，再由 AI 补房间名、摆家具。
  - **对话修改**：比如"主卧再大一点""阳台加窗"。AI 会结合最近的对话，并说明改了什么，或者为什么没改。
  - **历史记录**：对话框下方的历史按钮以缩略图列出每一版户型（AI 生成、手动修改、识别导入），可以恢复任意一版，恢复本身也能再撤回。
  - **交付全部来自设计器本身**：报价单、A3 施工图 PDF、DXF（平面布置、水电点位、拆改）、彩平图和 3D 效果图。

- **`cad-skill` 与画布流程一致，可以独立运行**
  - 整个文件夹拷到任何项目都能用。有原始户型图就直接生成设计器网页；只有需求时先和你商量好方案和待定事项（宿主有选项工具时直接点选），再布局、生成户型。
  - 之后自动完成设计：推开碰撞的家具、布水电、应用水电偏好、做检查和水电审计，并导出报价单 CSV、施工图 PDF、DXF、彩平图和 3D 效果图。
  - 交付「户型名-装修设计器.html」：完整设计器的离线单文件，里面就是你的设计，跑完自动在浏览器打开。以后双击就能再打开，在里面做的修改会保存在这个浏览器里。
  - 交付前会对网页做一遍全功能验收。
  - 直接使用电脑上已有的 Chrome 或 Edge，不再下载浏览器：在 skill 文件夹里执行一次 `npm run setup` 即可。不需要 API Key，也不需要图像模型。

**⚡ 改进**

- 户型改为流式生成；模型输出中途被截断时会接着生成而不是报错，错位的 JSON 括号会自动修复，失败的步骤从断点重试，失败原因显示在对应步骤里。
- 流式 AI 调用会记录首字耗时和总耗时。

**🐛 修复**

- 从设计器切换到别处时，工作区不会再崩溃。
- 设计器运行出错时，设计不会丢失。
- 重命名房间会替换原来的名称，不会叠出第二个标签。

**📌 说明**

- 已移除：分析图板、AI 生成的材料清单、AI 绘制的效果图，以及旧的 SVG 绘图流程。所有图纸现在都来自设计器。
- 上传户型图时，服务器直接运行设计器的识别脚本（`server/recognizer/recognize.py`，调用 `skill/cad-skill/designer/scripts`），不用另开服务；服务器上要有 Python 并执行 `pip install -r server/recognizer/requirements.txt`（或用 `PYTHON` 指定解释器），否则上传按钮不显示。Docker 镜像已自带。
- CAD 的「交付检查」按钮在服务器上跑设计器的验收（`skill/cad-skill/designer/scripts/qa.mjs --lite --quick`，再跑 `qa_files.py`）；服务器上要有 Chrome / Edge / Chromium（或设置 `CHROME_PATH`）和装好识别服务依赖的 Python，找不到浏览器时按钮不显示。Docker 镜像已自带 Chromium。
- 水电审计只报告问题，不会自动挪点位；请在设计器的「水电」里调整。
- `cad-skill` 从原始户型图开始时需要 Python 和 `numpy pillow opencv-python pymupdf ezdxf pypdf`；只用需求设计时只要 Node 18 以上。

### 2026-11-06

**✨ 新增**

- **PPT 演示画布支持导出可编辑 PPTX**
  - 导出菜单新增「导出可编辑 PPTX」，和「导出 PDF」「导出图片版 PPT」并列。
  - 以前导出的 PPT 每页都是一整张图片，现在每页会拆回可以直接修改的图层，自下而上依次是：
    - **干净底图**：去掉文字、卡片、图标后的纯背景，渐变、波浪、建筑等背景元素保留在这一层；
    - **原生形状**：卡片底框、分隔线、圆点、圆环、色条、箭头等都是 PowerPoint 自带的形状，可以直接改颜色、大小、圆角；
    - **图标和插图**：由生图模型按原图重新绘制，背景透明，可以单独移动、缩放、替换；
    - **可编辑文字**：标题、正文、列表都在文本框里，保留原来的位置、字号、颜色和粗细。
  - 同一套风格的多页可以共用一张底图；多页重复出现的图标和卡片只绘制一次，整套 PPT 风格统一。

- **导出设置框**
  - **选择页面**：列出整套幻灯片的页码和标题，可以全选、全不选或逐页勾选，只导出需要的页。
  - **返工次数**：每页最多返工 3–10 次，默认 3 次。每页做完都会和原图对比检查（整体相似度、局部差异区域、文字位置和字号、抠图残留的绿边），不过关就自动修改再查；通过检查的页面提前结束，不会白白多跑。
  - 填写超出范围的次数时，会自动调整到最近的允许值。

- **导出运行窗口**
  - 点击开始后，导出按钮下方弹出固定高度的运行窗口，像 agent 运行一样实时滚动显示整个过程。
  - 按顺序列出 7 个步骤：识别文字 → 规划底图 → 生成干净底图 → 分析页面元素 → 生成图标与插图 → 逐页重建 → 合成 PPTX。每一步显示等待、进行中、完成或失败的状态和用时。
  - 每一步下面有带时间的明细，例如「第 1 页识别出 12 段文字」「底图 g1：第 1、2 页共用」「第 2 页：第 1 轮检查未通过（相似度 78.5，6 处问题），继续修改」。
  - 「逐页重建」按页分组，多页同时进行时各页的进度互不混在一起。
  - 正在进行的步骤和页面自动展开，完成后自动收起；手动展开或收起过的，保持你的选择。内容超出窗口高度时可以向下滚动，有新内容时自动滚到最新，往上翻看时不会被打断。
  - **中间产物可以点开看**：生成的干净底图、图标素材表、切出来的每个图标和插图、每页每一轮的成品图，以及标出问题区域的检查对比图，都以缩略图显示，点击直接放大查看。

- **`ppt-skill` 新增 `editable_pptx` 导出模式**
  - Claude Code、Codex 等编程助手也能把整套幻灯片导出为可编辑 PPTX，步骤和检查标准与应用里的导出一致。
  - 由宿主助手自己完成需要判断的环节：看图规划底图分组、分析每页元素、写每页的合成说明、根据检查结果返工，不用另外配置对话模型。
  - 机械步骤由 `editable/editable_run.py` 完成（识别文字、生图和重试、比例检查、按图形切图、合成、PowerPoint 导出预览、检查、合并），按 `init → base → analysis → assets → page / check → merge` 依次执行；完整步骤写在 `references/editable-pptx-workflow.md`。
  - 读取和图片版 PPT 相同的幻灯片清单，JPG、WebP 等格式会自动转换；运行目录保留底图、素材表、每轮成品和检查图。
  - skill 自带所需的全部脚本和规则文档，不依赖应用代码，单独拿走也能用。
  - 生图模型和其他导出模式一样，读 skill 里的 `config/image-provider.json`。

**⚡ 改进**

- 导出期间可以把运行窗口收起成导出按钮旁的计时小标签（显示已用时间），继续编辑其他页面，点一下标签就能重新展开。
- 导出完成后窗口自动关闭，文件自动下载；导出失败时窗口保留，显示失败在哪一步和原因。
- 刷新页面、关掉再打开页面或服务重启后，正在进行的导出会自动接上，之前的步骤明细和中间产物都还在，完成后照常下载。
- 背景识别更准：分析页面元素时会拿干净底图对照，背景里的渐变、波浪、建筑不会被误当成元素重复绘制。
- 底图比例和原图不一致时会自动重画，不会拉伸变形。
- 图标素材表画出来的数量不对时会作废重画，不会把错位的图标切进 PPT。
- 已有一个导出在运行时再点导出，会提示「已有一个导出任务在运行，请等它结束」，不会互相干扰。

**📌 说明**

- 可编辑导出需要逐页生成和检查，比较慢，通常需要 10 分钟以上；同一时间只运行一个导出任务。
- 图标和插图是按原图重新绘制的，设计一致，但不会和原图逐像素相同。
- 运行环境：需要安装 Microsoft PowerPoint（用于导出预览做检查），Python 依赖用 `pip install -r scripts/slide-agent/requirements.txt` 安装；所需的脚本和规则文档都在 `scripts/slide-agent/` 里，不用另外安装。
- 模型配置：在 `scripts/slide-agent/.env.local` 或环境变量里配置一个对话模型（`SLIDE_AGENT_API_KEY` / `SLIDE_AGENT_BASE_URL` / `SLIDE_AGENT_MODEL`）和一个生图模型（`SLIDE_AGENT_IMAGE_API_KEY` / `SLIDE_AGENT_IMAGE_BASE_URL` / `SLIDE_AGENT_IMAGE_MODEL`）。
